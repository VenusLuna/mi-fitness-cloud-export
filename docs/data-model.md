# 数据解析与当前状态视图

## 保存格式

SQLite 表包括 `meta`、`cursor`、`pages`、`records`。`records` 用内容 SHA-256 去重；同一时间记录被修订后内容不同，会保留多个版本。这是可审计原始日志，**不是直接可相加的最新状态表**。

JSONL 每行包含 `stream`、`raw`；定时增量导出另外包含二次解码的 `value_decoded`。CSV 中的原始字段和未识别字段保留，不擅自换算单位。字符串以 `= + - @` 等开头时做公式注入防护。

## 二次解析

```python
import json

record = {"key": "weight", "value": '{"weight": 60.0, "fixture": true}'}
value = json.loads(record["value"])
assert value["fixture"] is True  # 人工示例，不是真实数据
```

`raw.time`、`update_time` 只有在确认是秒时才按秒转换。解析器显示 UTC+08:00，原始时间和时区信息仍保留；不会把毫秒形数字猜成秒。

## 删除与更新

分析前按账号、数据流、类型、记录时间等协议身份选最新 `update_time`，注意：

1. `deleted=true` 是删除标记，`value` 可以为 null。先处理删除状态，不能把旧版本重新当作现存数据。
2. 删除标记有时缺少 `sid`；不要只按包含 sid 的键合并，导致删除无法匹配。反过来也不能在多个设备确有不同记录时无条件合并。遇到来源冲突应保留并标记歧义。
3. 睡眠结束时间改变可能产生不同记录时间，同一次 bedtime 的中途 `is_uncomplete=true` 版本不能与最终睡眠重复累计。
4. `has_rem=false` 时，REM 时长 0 不能解释为真的没有 REM。
5. HRV、睡眠分期、活动目标数字编码与单位要按该协议逐项验证；公开端侧 SDK 的字段名称相似，不代表云端编码和单位相同。

## 体脂秤注意事项

- 同一人体的晨间、晚间记录并非同条件对照；优先用同时间、同条件记录建立趋势。
- `weight`、`body_fat_rate` 与各组织估算量不是独立医学测量，不能把每个字段都解读为确定的生理变化。
- 用户资料、设备来源与数据是否进入此健康云端应由本人确认；字段集合不能证明设备一定为某个型号。

## 运动与轨迹

`sports.key` 表示运动项目类别；不代表识别了力量训练的每一个动作。运动总时长可能包含休息，热量是设备估算。摘要没有经纬度，不代表独立 GPS 文件不存在。FDS 解码见独立文档。

## 完整性

输出明确保留 `full_history_verified=false`。时间窗口首屏响应、有数据、业务码成功、游标到页尾和 Apple Health 同步是不同事实，不能相互替代。
