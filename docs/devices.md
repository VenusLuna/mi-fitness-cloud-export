# 两类设备分别怎么获取数据

## 小米手环

1. 在小米运动健康里完成本人设备绑定，先让手环和手机同步；检查 App 中记录的日期确实更新。
2. 用本仓库的官方网页登录流程建立**本人健康云会话**，不是直接拿普通账号网页 Cookie 调业务接口。
3. 运行 `cloud_export_web.py sync --streams fitness,aggregated,sports,project`。保存的原始数据和游标只在本地私有目录。
4. `fitness` 提供心率、睡眠、步数、血氧、压力等记录；`sports` 提供运动类别和摘要。按 `key` 和二次解码 `value` 识别，未知字段原样保存。
5. 户外运动的轨迹可能单独保存在 FDS，不能在摘要里找不到经纬度就判断无轨迹；按 [FDS 方法](fds.md) 手动核查。

腕上采样频率、佩戴情况、是否带手机定位、手机后台限制和 App 上传状态都会影响结果。云端拉取不能补造设备未采到或尚未上传的数据。

## 小米体脂秤（例如 S400）

1. 先按设备官方说明完成绑定、称量与同步。某些设备以米家为入口；不要把本文的登录流程当成米家设备接入教程。
2. 确认目标体重/体成分记录**实际出现在本人小米运动健康账号的数据中**。米家同账号登录、蓝牙网关在线或称量成功，本身都不是这一步成立的证据。
3. 如果已经进入该健康云端，运行同一个 `fitness` 水位同步，不需要另一套体脂秤解密算法。体成分是 `key=weight` 的记录；后续新增称量由游标持续获取。
4. 使用 `parse_health.py` 二次解析 `value`，在私有输出目录查看以 `fitness__weight-` 开头的 CSV 和 `summary.json`。保留未出现的字段为空，不伪造完整指标数量。
5. 如果健康云端没有这些记录，当前仓库不会自动去米家云找，也没有实现直连 BLE；需要针对实际米家同步链路另行研究，不能靠换一个用户ID或忽略业务错误解决。

体脂秤数据可能包括体重、BMI、体脂率、脂肪量、肌肉量、骨骼肌量、水分、蛋白质、骨量、内脏脂肪等级、基础代谢和一次性心率。字段集合只能说明该记录包含这些指标，不能单凭字段断言具体硬件型号或准确性。

## 两者共用的解析命令

```sh
.venv/bin/python cloud_export_web.py sync \
  --streams fitness,aggregated,sports,project --max-pages 40
.venv/bin/python parse_health.py private/health.sqlite \
  --sqlite --out private/parsed-new-run
```

解析输出不是已脱敏样例，其中有真实测量时间、来源标识和健康值，应和 Token 一样留在私有位置。Apple Health 是否写入是另一条链路，这些命令不读取或修改 HealthKit。

## 识别失败而不是假装成功

- 凭证过期：在本人官方登录流程重新授权，不分享 Token。
- HTTP 成功但业务码非零：按失败处理，保留私有证据，不视为空数据。
- `project` 空列表：只说明此接口当前返回为空，不表示没有运动种类。
- `full_history_verified=false`：不应宣传“全部数据已拿到”。
- 同一记录有修订或删除：原始库保存版本，统计时需要建立当前状态视图，见 [解析说明](data-model.md)。
